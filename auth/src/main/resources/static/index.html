Los Elementos del Versus

Stateful vs Stateless

Session-Based (Stateful): El servidor almacena el estado (sesión) en su memoria o en una base de datos distribuida (Redis). El cliente recibe solo una clave de referencia (Session ID) dentro de una cookie. La validación requiere buscar ese ID en cada petición.

JWT (Stateless): El servidor firma un token (JWT) que contiene toda la información de la sesión. El servidor no retiene nada del estado. La validación se hace verificando criptográficamente la firma. No requiere consulta a base de datos.

HTTP y el Estado

HTTP es por definición sin estado. Cada request es aislado. Para retener el estado se usan dos técnicas principales:

  • Cookies HTTP: Manejadas automáticamente por el navegador. Tienen ventajas de seguridad importantes si se configuran como HttpOnly (prevención contra robo de cookies mediante XSS) y Secure/SameSite.
  • Authorization Headers: Enviar el token manualmente en la cabecera Authorization: Bearer [token]. Requiere que JavaScript almacene y manipule el token, aumentando la superficie de ataque XSS.

El Trilema de Autenticación

Intentar lograr tres objetivos en conflicto:

  • Seguridad: Capacidad de revocar el acceso de forma inmediata (por robo, cambio de contraseña o bloqueo de administrador).
  • Performance: Validar peticiones rápidamente, idealmente con cero latencia de base de datos (Zero DB Lookups).
  • UX: Mantener al usuario logueado de manera transparente (Silent Refresh).

Nota: Si buscas seguridad absoluta, JWT pierde su carácter stateless porque requiere consultar una base de datos o blacklist en cada petición.

El Dilema de la Revocación Inmediata

En un sistema JWT puramente stateless, si un administrador bloquea a un usuario, su Access Token sigue siendo válido en todo el internet hasta que expire de forma natural. Para solucionarlo, debemos añadir una base de datos de tokens bloqueados (Blacklist) o validar al usuario en la BD en cada petición, lo que devuelve el sistema a un esquema stateful.

Seguridad

Revocación instantánea en Sesiones. En JWT requiere "Blacklists" en base de datos.

Performance

JWT gana en escalabilidad pura por validación local de firma sin llamadas a DB.

UX (Session Lifespan)

Sesiones auto-renovables vs JWT con flujos complejos de Refresh Token silencioso.
